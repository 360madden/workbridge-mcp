### Hard limits: not yet proved

- **No live GUI/API/input/VM/RIFT/OneDrive action** and no canonical `.tools/desktop-evidence` lock or deployed `dist` change; the native executable is not integrated into Workbridge.
- The "process abort" scenario is an explicit `Environment.Exit(91)` of the owned disposable helper child, **not** a forced OS crash/dump; it proves lock retention after that exit form only.
- This test proved same-leaf **acquire contention** and a **pre-release same-byte replacement**. It did **not** race a rename while the release helper holds a native DELETE handle. That barrier-controlled case and a hardlink/reparse/share-denial matrix remain required for R1.
- The test runner bounds owned child processes to eight seconds and uses Windows-hidden, shell-free calls; it does **not** independently establish a Windows Job Object descendant-settlement guarantee. No child-tree claim is made.
- The tool's environment-derived OS TEMP root and test-only `--existing-root` are not a general security sandbox. This prototype refuses arbitrary paths, workspace-root TEMP and canonical production names; production helper design must add fixed canonical allowlists, source/runtime helper SHA verification, and reliable owner settlement.
- A native release receipt means only a **file-lock postcondition**, not an action result. Any future Workbridge source integration, crash-handling changes, backup, live deployment or rollback must follow a separate, approved WB-001 milestone.
