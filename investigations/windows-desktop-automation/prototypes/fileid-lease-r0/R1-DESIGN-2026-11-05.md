## Instrumentation and decision gates

- An optional `release --test-barrier-timeout-ms N` mode, `1 <= N <= 1500`, is restricted to the existing GUID-only OS-temp fixture roots. After native `CreateFileW(OPEN_EXISTING)` with DELETE access and `FILE_SHARE_READ`, original volume/128-bit FileId, ordinary-file/link count, exact SHA+lease and post-read native ID checks, it emits one flushed `{"ok":true,"stage":"pinned"}` progress line and **waits with the SAME OS handle open for an exact `ACK` line on stdin** for at most 1.5 seconds. The Node contender attempts rename *before* sending `ACK`. Only after valid ACK may it call `SetFileInformationByHandle(FileDispositionInfo)`; missing/invalid ACK returns an explicit **retained-lock** error, never a delete. Without this option, the R0 one-result protocol remains unchanged. There is no path unlink fallback or production lock basename.
- The R1 harness `r1-synthetic-run.mjs` accepts **exact absolute R1-built EXE path + its SHA-256** before any test fixture mutation. It rejects unsafe or redirected TMP/TEMP outside the current user's canonical LocalAppData Temp, reparse-derived real paths, Workbridge/root/RIFT/VM/OneDrive paths; verifies native temp root SHA on every native create, and uses GUID temp leaves only.
- All child launches are owned and shell-free: native helper uses bounded `spawnSync` (8 seconds) or `spawn` (5.5 seconds) and no console; the sharing-violation case launches a single owned Windows PowerShell 5.1 `[IO.File]::Open` holder for 1.5 seconds and observes its readiness/exit. No arbitrary PID kill, task start/stop, process inventory, service restart or input. These are *owned-process timing bounds*, not a Job Object-descendant proof.
- A **fresh separate source-review GO** and **explicit root authorization** are required before a single R1 build or test job. Keep source frozen after peer pinning. Reconfirm the live Workbridge source fingerprint and absolute ignored build path; do not run against R0's older frozen compiled EXE.

### Anti-false-green requirements

1. If any `spawn` child lacks readiness, times out, changes exit code or emits malformed/multi-line protocol unexpectedly, explicitly **reject the pending readiness promise immediately**, retain fixture and mark **failed/unknown**, not passed. Do not fire another release when prior result is uncertain.
2. Do not turn missing Windows symlink privilege into a "green" reparse proof. Stronger R1-R2 coverage later needs both directory junction and leaf reparse, plus hardlink identity and parent no-follow checks.
3. `FILE_SHARE_READ` without `FILE_SHARE_DELETE` should prevent the competing rename while helper's held handle is open; Windows filesystem semantics and scan filter interference may differ. The **ACK ordering** makes the contender attempt happen-before disposition rather than depending on a 1.2s wall-clock sleep; the barrier test is designed to **falsify** that assumption before production use.
4. A negative exit must be supported by the preserved leaf/alias bytes and exact native receipt, not merely an error string. Native `RELEASED` is only file-lock evidence, not action delivery.
5. The helper source still targets only synthetic `synthetic-fileid-lease.lock`. Before any actual provider integration, replace OS-temp discovery with a separate, production-hardened fixed canonical evidence-root allowlist and signed/manifested native dependency, then separately validate full producer/lease and descendant-settlement contracts.
6. The optional benchmark creates and retains 40 synthetic GUID directories; parent approval must explicitly cover their temporary disk footprint and any later exact-ID cleanup. Do not perform an unbounded performance loop.
