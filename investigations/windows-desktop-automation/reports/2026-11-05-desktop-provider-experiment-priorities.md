**Date:** 2026-11-05 (America/New_York). **Owner:** independent provider/architecture review. **State:** investigation-only, no GUI, input, screenshot, VM, lock, or production service changes by this reviewer.

## Decision in one sentence

**Keep Workbridge's currently working desktop functions and 36-slot coordination, now shift the first *new* pilot from quarantine recovery to disposable-host UIA/dialog evidence, and add interchangeable providers only for functions they actually prove better.** Use existing Microsoft WinApp CLI 0.7.1 first; assess pinned `sbroenne/mcp-windows` v1.3.28 next under its isolated verified process owner. Do not assume FlaUI, OCR, or a new framework solves game-rendering/VM guest boundaries.

Prove two independently fresh nonblank frames and a reference target before considering coordinate action. | Moderate/high; defer until a real semantic gap measured. | Blank/minimized, ambiguous OCR or DPI, unverified event. |
| **P6** | 🟠 Guest Lab2 OneDrive read-only UIA only after RR2 guest session and receiver/lease health are independently re-established; Lab1 separately blocked. | Separate project phase, not a host desktop benchmark. | Unknown guest identity, game foreground disruption, queue/cleanup unknown. |

**Efficiency implication:** Start with **P0 → P1 → P2 → P3**, not all providers or labs simultaneously. The 36 Workbridge job slots permit parallel source/fixture/test design, but **one shared interactive GUI turn per desktop**. Event-based `ui_wait` is promising for modal latency, but only a *fresh observed target condition* plus a post-action oracle proves the wait worked; do not measure “sleep returned” as dialog success. Keep cold startup and provider-only UIA separate. Do not allocate 30 paired blocks until one clean pair and a small 5+5 sample actually reveal actionable differences.

## Go/no-go for adoption

- **Keep:** Workbridge current four deployed `desktop_*` tools and specialized RIFT host input/screenshot workflows; preserve prior one-shot receipts.
- **Pilot:** sbroenne per-function read-only in a bounded, private, exact HWND MCP server; Microsoft WinApp as baseline.
- **Reference:** eugman modal pending-operation tracker; UIInspect/trsdn for legacy accessibility; native Win32 for window identity; WGC/OCR for clearly proven semantic gaps.
- **Defer:** general desktop click, arbitrary third-party Save/Overwrite, guest OneDrive GUI, Lab1, RIFT renderer coordinates, new always-on desktop daemon, production desktop-provider replacement.

Every possible promotion requires correctness and after-state, stale-HWND, modal/hung-provider behavior, p50/p95/full latency, complete owned descendant settlement and rollback, then separate WB-001 release. Do not replace an incumbent based on a new provider's feature list or protocol handshake.
