# Node desktop-lock release: held-handle remediation roadmap

**Date:** 2026-11-05 (America/New_York). **Status:** DESIGN ONLY, not implemented, tested, installed or deployed. This document authorizes no runtime/UI/VM/RIFT/OneDrive changes, guard archival or Workbridge owner restart. Preserve day-to-day Workbridge. Rollout is a future separately approved WB-001 maintenance operation.

## Recommendation and scope

**P0 choice: a small, pinned .NET 10 Windows native lease helper, used for BOTH creation and release of each lock**, called by Node with bounded shell-free IPC. It returns the original native `FILE_ID_INFO` (volume serial + 128-bit file ID) at `CREATE_NEW`, then uses `CreateFileW(OPEN_EXISTING)`, rechecks that exact ID and stamp on an opened handle, and invokes `SetFileInformationByHandle(FileDispositionInfo)` on **that handle**, never `unlink(path)`. This is the smallest independently deployable solution with an exact cross-process Windows file identity and no always-on broker. Benchmark the two native launches per lock before declaring the latency acceptable.

**Why creation must change too:** a release-only helper receiving only Node's `stat().dev/ino` and a stamp hash lacks a proven, full native `FILE_ID_INFO` from the file originally created. If an identically stamped different file replaces the name before the release helper opens it, neither content hash nor PID proves original ownership. Do not assume Node's `ino` maps byte-for-byte to Windows' 128-bit file ID without a dedicated Windows conformance proof. Existing native C# watchdog/archiver code provides useful P/Invoke patterns, not a production-ready generic deletion tool.

## Minimal provider-neutral interface (proposed)

Place source in `scripts/helpers/DesktopLeaseNative/` (separate from DesktopProbeWatchdog prototype) and a slim wrapper `scripts/desktop-lease-native.mjs`. The Node API can keep existing `acquireDesktopAdmission` / `releaseDesktopAdmission` / `withDesktopAdmission` exports and freeze/`WeakMap` ownership. Introduce equivalent `acquireDesktopGuiTurn` / `releaseDesktopGuiTurn` internal helpers for writers, without changing public MCP tool names, requested target identities or existing on-disk stamp schemas.

| Verb | Exact native behavior | Node-visible result |
| --- | --- | --- |
| `create` | Validate one approved `.tools/desktop-evidence` parent and literal basename (`desktop-turn-admission.lock` or `desktop-input-turn.lock`), ordinary non-reparse components, bounded schema-1 JSON+newline bytes, role and owner/request. `CreateFileW` with `CREATE_NEW` + `GENERIC_READ/WRITE/DELETE` + restrictive share mode; write+FlushFileBuffers; read native `FileIdInfo` on **creation handle**; close. Never clean an uncertain partial create. | Opaque in-process token: role, canonical parent, original volume/file ID, exact SHA/length, lease/admission/request IDs, owner PID/start/session where known, helper/protocol digest; no secret/token printed in ordinary logs. Lost response after creation = **unknown, name retained; no automatic retry**. |
| `release` | Reopen the literal approved leaf with `OPEN_EXISTING`, `FILE_FLAG_OPEN_REPARSE_POINT`, DELETE access and **no FILE_SHARE_DELETE**; reject directory/reparse/hardlink, delete-pending, oversized or malformed source. Pin `FileIdInfo`, verify expected original volume+128-bit ID, exact bytes SHA/length and stamp owner/role; while handle remains open, call `SetFileInformationByHandle(FileDispositionInfo)` then close. Treat deletion refusal or uncertain name absence as recovery-required. | `RELEASED` only on a verified same-file result and canonical absence. `FOREIGN`, `BUSY`, `UNKNOWN`, helper crash/timeout or malformed response never trigger `fs.unlink` fallback. |
| `probe` (testing only) | Non-destructive identity/read inspection in a unique synthetic directory. No production "force" or "remove stale" mode. | Bounded diagnostic for synthetic harness; never an admission override. |

Node invokes a SHA-pinned fixed native executable via `execFile`/`spawn` with explicit executable path, `windowsHide`, no shell, bounded stdin JSON, stdout/stderr byte caps, child PID+creation and timeout tracking. Check **both** process exit and protocol/receipt status; a wrapper's exit-0 alone is not outcome proof. No command-line passwords, arbitrary file paths or untrusted delete-by-name mode. The helper should report one versioned structured receipt, never silently retry after a possibly completed mutation. Create and release can use a single helper executable; each invocation is short-lived and not a new Workbridge service.

**Identity/focus separation:** This locks *host GUI turns only*. It does not authenticate the Windows interactive session, target HWND/PID/start time, VMware guest, OneDrive, WinApp/Sbroenne backend, input result or screenshot postcondition. Existing producer validation and independently collected before/after evidence remain mandatory.

**Failure order:** Admission created first, old GUI guard second, action third. If action is definitely complete and child tree settled: release exact GUI guard first, then admission; persist receipt. If action is uncertain: retain guard and linked sidecar and mark prior input outcome unknown; release admission only when the retained guard+sidecar veto is independently verified. If either guard ownership or sidecar is unproven, retain admission as well. A native helper `Dispose`/process crash closes OS handles **without automatic removal** unless `FileDispositionInfo` was explicitly and safely issued. No age/PID-based steals, silent auto-unlock, or repeated input.

The current Node `withDesktopAdmission` always runs release in `finally`. Before P2 production promotion, introduce a small *fail-closed settlement result* or retained-guard proof, so GUI cleanup failure cannot be silently followed by admission release when no trustworthy old veto remains. Do not infer action success from a helper exit code.

## Options comparison

| Backend | Engineering size | Release identity | Added latency / packaging | Decision |
| --- | --- | --- | --- | --- |
| **Pinned .NET 10 one-shot native EXE + Node wrapper** | **Small-medium**, reuses proven C# P/Invoke idiom; no resident worker | Exact original 128-bit `FileIdInfo` carried from native create to held-handle release | **2 process starts per lock** (admission + GUI = up to 4). Bundle binary/dependencies and hash-pin in WB-001; measure cold/warm. | **GREEN: first synthetic implementation** |
| PowerShell 5.1 `Add-Type`/PInvoke bridge | Source packaging smaller | Can implement same create+held-handle release | Multiple powershell launches/compilation, quoting/capture/timeout and PowerShell-version variation; poor candidate for high-frequency GUI work. | **YELLOW: maintenance/prototype only** |
| Node N-API native addon | Larger build/ABI/toolchain+signing matrix | Could act on real original CRT file descriptor/OS handle with careful ownership | Very low call overhead; risky FD↔HANDLE marshalling, Node upgrade and packaging complexity. | **YELLOW: optimize only if benchmark fails** |
| Persistent per-turn .NET lease broker | Larger IPC/lifetime/supervisor work | Original handles remain in one process until explicit settled release | One startup for whole turn and cheaper repeated operations; broker crash leaves a blocking orphan. | **DEFER** pending measured one-shot latency |
| Existing `fs.unlink` after hash and Node `dev/ino` checks | No change | Pathname **not** bound across check/delete | Fast but leaves identified gap | **RED: do not retain for migrated release** |

The helper should first be a framework-dependent Windows-x64 build if .NET 10 runtime availability is confirmed, or a sealed self-contained publish if needed; NativeAOT is **not** mandatory for correctness. Both multi-file deployment and cold startup performance must be measured. Publishing artifacts cannot simply be added to the current **text-sized six-file** desktop stager without changes.

### Compatibility and explicit non-goals

- Keep on-disk `schemaVersion:1` admission/GUI stamps, `requestId`, `leaseId`, `owner`, quarantine sidecar fields and MCP tool names; initially version **the helper IPC and in-memory native identity token**, not the user-facing action API. If a future disk schema must change, old and new runtime must reject unknown versions and WB-001 must enforce an all-producer cutover.
- Retain legacy `desktop-input-turn.lock` as the second veto until all known GUI producers and recoverers use the same admission/guard contract. Do **not** implement a "repair stale lock" shortcut in the helper. Operator recovery still uses separate exact-file archival and an approved admission-freeze protocol.
- Retain historical receipts, image hashes, request-id no-replay, process-tree settlement, GUI session and target proofs. A native `RELEASED` means only **lock release**, never proof that a click, dialog, OneDrive sync or RIFT action succeeded.
- Current `desktop-runtime-manifest.json` pins six staged files; the published standalone watchdog source/binary parity, direct physical-RIFT scripts and future Sbroenne/FlaUI/WinApp adapters remain **separate release-coverage checks**.
- Do not modify active Workbridge `.local`, tracked deployed `dist`, canonical desktop guards, Windows Tasks, RIFT/VMs, OneDrive, or human foreground in this design milestone.

## Primary API and repository evidence

- Microsoft `SetFileInformationByHandle`: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle (DELETE access required for `FileDispositionInfo`; delete marked on held handle, applied on close).
- Microsoft `FILE_ID_INFO`: https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info (volume serial and 128-bit file ID).
- Microsoft `CreateFileW`: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew (creation disposition/share-mode preconditions).
- Node file API `fsPromises.unlink(path)`: https://nodejs.org/api/fs.html#fspromisesunlinkpath (pathname operation; no raw Windows handle-bound disposition API).
