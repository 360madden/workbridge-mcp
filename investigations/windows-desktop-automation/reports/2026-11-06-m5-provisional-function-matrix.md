# M5 provisional function-by-function desktop-provider decision — November 6, 2026

**Owner:** independent Workbridge provider-review lane. **Scope:** evidence-backed recommendation only, not a replacement plan or permission to run GUI actions. Workbridge 0.16.4-dev stays the operating coordinator, with its four deployed desktop tools, 36-slot command scheduler, GUI admission, exclusive desktop turn, incident journal and recovery. The 36 command slots **do not** authorize concurrent input on one desktop.

## Read this table correctly

- 🟢 **KEEP** = preserve the installed working path; 🔵 **WRAP** = keep Workbridge ownership and add a narrowly bounded backend; 🟡 **PILOT** = controlled observation against a disposable fixture; 🔴 **DEFER** = no general deployment or real-user input.
- **L** = historical actual narrow host Windows/RIFT run (specific surface only); **S** = offline synthetic/tests or controlled host capture, not vendor GUI parity; **P** = native build/protocol/Job receipt without a UIA call; **C** = source/API/documentation only; **U** = not measured, not proof of inability.
- A result from a provider (tool success, pending ID, screenshot hash, process exit0) is not independently verified application effect. D1's 22/22 offline outcome tests and M3-P12's 18/18 parity tests establish **pure rule behavior only**, not real desktop reliability.

## Two small disposable GUI trials that would most improve the ranking

**Trial 1 — P1: exact-HWND DesktopProbe READ-ONLY UIA parity, WinApp then sbroenne.** A single **source-pinned, nonactivating** disposable WinForms fixture with fixed Window/IncrementButton/ResetButton/CounterDisplay, never physical RIFT/OneDrive. In one user-approved quiet desktop window, independently pin watchdog PID+birth+SID and child's PID+birth+session+HWND, original foreground, visible rect and starting/shown journal, before any provider call. Require the fixture to actually appear **without taking focus**; if its existing build cannot guarantee that, use a separately reviewed no-activate fixture or STOP. Obtain atomic Workbridge admission and one quiet-owner lease, run one strictly read-only depth1 inspection per backend (**Sbroenne --tools ui_snapshot only; never ui_find/ui_read**) in **separately isolated, Job-contained** processes, project only typed-ID witness counts and stable journal hash; compare before/after and Job0. A backend that changes foreground, fails type uniqueness, leaks UI text or leaves a child => FAIL/HOLD. First clean pair only; measure WinApp app-inspect and Sbroenne ui_snapshot independently, plus whole-call cost; no auto-follow-up.

**Trial 2 — P2: exact owned-modal DETECTION / late arrival and no-input wait.** Use a separately reviewed **nonactivating disposable owner+owned-dialog fixture** with fixed native HWND owner relationship and a timed ~350ms synthetic appearance; the timer/journal belongs to the fixture, **not** an AI click. Use WinApp+native owner observation first; compare sbroenne ui_wait **only after a separate source review and explicitly expanded tool allowlist**, and treat eugman's pending-tracker ideas as design references unless its runtime is independently pinned. Verify owner HWND/process start/session and two fresh appearance/disappearance journal transitions, bounded wait, stable foreground and zero input/clipboard/screenshot; on lost UIA, bounded helper deadline, live owner or missing after proof => UNKNOWN and retained evidence. This tests owner matching/wait feedback, **not** authentic common File Save interaction. Any true modal that forcibly activates cannot meet this no-focus pilot and must be deferred to a separate specifically approved focus-changing test.

**Both require a fresh user quiet-window confirmation and preflight immediately before launch:** no active Workbridge GUI turn/admission/quarantine, no other UI owner, no RIFT gameplay, no guest VM controls in flight, default WinSta0/Default interactive session, verified monitor and original foreground. Never grab foreground, type, click, use clipboard, alter VM power/OneDrive sync, dismiss a dialog or retry a timed-out provider. Child/private Job lifecycle, event journal and native before/after guard must all settle. A previously clean Nov5 guard check is **historical**, not permission today.

## Decision

**Keep Workbridge and WinApp for day-to-day host work; spend engineering effort first on a reliable native observer + interchangeable single-function read-only UIA backend.** Pilot Sbroenne on actual same-target snapshot and owned-modal observation. Reuse eugman's modal tracker as an algorithm only if measured evidence shows a gap. Keep native RR2/RIFT and guest-side OneDrive diagnostics as distinct specialist systems. No current evidence justifies replacing all desktop functions, multiplying concurrent GUI agents or installing an always-on desktop controller.
