## Critical-path evidence

| Gate | Source assessment |
| --- | --- |
| 🟢 Host outside private Job | `SbroennePrivateJobV2.Create` creates unnamed non-inheritable Job, sets `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` without breakaway, rejects own-host membership, requires initial `Active()==0` and empty PID list. The host should survive closing its own child Job and propagate a real exit status. |
| 🟢 STARTUPINFOEX ABI and handle list | `StartupInfo` field order/types, `StartupInfoEx` appended attribute pointer, `PROCESS_INFORMATION`, pipe SECURITY_ATTRIBUTES and `CreateProcessW` P/Invoke are structurally consistent with x64 Win32. The handle list key `0x00020002` is `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`. Child-inherited pipe **stdin read + stdout write** are explicitly inheritable; parent ends have inheritance removed; stderr aliases stdout. Attribute storage survives until `CreateProcessW` returns; initialized list is deleted in `finally`. With this attribute, `bInheritHandles=true` is required and present. No pseudo handles in inherited allowlist. |
| 🟢 Suspended/assigned before running | `CreateProcessW` uses exact hash-pinned Node executable + script, literal command, `CREATE_SUSPENDED | CREATE_NO_WINDOW | EXTENDED_STARTUPINFO_PRESENT`. It returns suspended handles; `job.AssignSuspended` checks an initially empty private Job, assigns exact process handle, verifies assignment+single PID, and checks host remains out of private Job. `ResumeThread` is invoked **only after** that method returns. Failed Create/transfer forcibly terminates exact unresumed process handle in `finally`; failed assignment follows host catch/kill, with no resume. |
| 🟢 Dynamic process accounting and cleanup | `Members()` resizes Job PID buffer up to 8192 and rejects incomplete counts, invalid/duplicate PIDs. `Snapshot()` checks `ActiveProcesses` before and after. `WaitEmpty` needs three consecutive empty snapshots. Clean `RESULT:success:SYNTHETIC_ONLY:none`, child exit0 and empty Job precede `HOST:SETTLED:0`. Error route calls exact Node termination + `TerminateJobObject`, checks empty Job and returns **3** for settled negative or **4** for uncertain. Host itself is not a private-Job kill target. |
| 🟢 Output/privacy and scope | The only accepted mode is `synthetic clean|forced-failure` with bounded request ID. Pinned source cannot call MCP/UIA, screenshot, focus, mouse, keyboard, VMware or RIFT. Native host prints fixed protocol tokens/PIDs/duration, not arbitrary child stdout, stderr, UI names or values. The 4096-character line reader rejects malformed/unbounded protocol. |
| 🟡 Some identity proof deferred | Host `job.Contains` checks exact Node and synthetic child's current handles, but the `members` array is not expressly required to contain both their PIDs before `HOST:READY_MEMBERS`. Add a literal membership check and save each process's creation time, owner SID/session/path and primary `CreateProcessW` handle birth for later provenance. |
| 🟡 Untracked auxiliary outside private Job | A `conhost.exe` could be spawned by Windows console creation before Node's primary thread resumes or through OS infrastructure. The private Job's complete PID list only proves who is **inside**; it cannot rule out an escaped auxiliary. For strong containment compare bounded OS process/parent/session and the outer Workbridge Job inventory. Additional members *inside* are currently accepted only if exact known OS `conhost.exe` image path, session and tight creation window match; source checks do not establish Microsoft code signature or provenance. Fail closed on identity ambiguity. |
| 🟡 Response binding and timing | Success/blocked receipts do not echo the request ID, exact binary hashes or process start ticks for an independent result normalizer. The sequential 12s/15s/10s/12s waits plus cleanup can approach the Workbridge 55s outer timeout. Capture exact OS exit, Job 0, unique request ID and durable timing envelope; never equate `HOST:BLOCKED` with success because the generic worker reports OS exit0. |
| 🟡 Source pin TOCTOU | Node/script SHA checks before spawning, but the shared script's on-disk contents might change between hash and Node file open under concurrent development. For stronger gates consider a private hash-pinned immutable copy and rehash/lock after startup, not a production-path or global change. |

## Go / hold decision and required synthetic receipt

**GO** a single *no-GUI synthetic-only* run after verifying fresh executable SHA and exact args. ## Immediate synthetic finding after initial source review

Author-reported first clean native V2 synthetic returned `HOST:BLOCKED:ATTRIBUTE_SIZE_INVALID:JOB_EMPTY:1`, OS exit **3**, before any child `CreateProcessW` launch. This does **not** establish clean containment or provider usability. Inspection found an unjustified minimum 64-byte bound at `Sbroenne-Provider-Host-V2.cs:124`: Windows' `InitializeProcThreadAttributeList` sizing contract supplies its required buffer size; no documented 64-byte minimum applies. Accept a **positive** returned allocation size within the chosen upper cap (currently 8192 bytes), optionally also assert the expected first-call `ERROR_INSUFFICIENT_BUFFER` (122), then validate the second initialization call. Rebuild/hash-pin before a fresh *separately authorized synthetic-only* retry. The existing blocked/exit3 receipt is useful negative-path evidence, but **not** a pass of a resumed suspended child. These are the author's runtime observations, not a command I ran.
